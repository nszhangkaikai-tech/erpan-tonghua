## 一、项目背景与核心目标

**伴梦童话**是一款面向 **3–10 岁亲子家庭**的微信小程序，核心定位是"定制化童话故事生成器"。

- **核心价值主张**：家长通过向导式输入（主题 / 场景 / 教育目标 / 主角设定 / 时长），一键生成专属的**图文 + 语音**童话故事，并支持**克隆家长声音**为故事配音，给孩子最本真的睡前陪伴。
- **目标人群痛点**：家长没时间编故事、不会讲、声音不在身边；市面通用故事缺乏"我家孩子"的专属感。
- **产品闭环**：故事生成 → 有声化（TTS / 声纹克隆）→ 故事日记本沉淀 → 收藏 / 分享 / 邀请裂变 → 兑换码权益体系。

### 技术全景

| 层 | 选型 | 说明 |
|---|---|---|
| 小程序前端 | Taro v4.2.1 + React 18 + TypeScript 5.8 + Sass | 主包 ≤1.5MB + 3 个分包（voice / library / user-center） |
| 后端 | CloudBase 云函数 `mp-user / mp-story / mp-voice / mp-cdkey / mp-admin` | Node，无服务化，已上线 v1.1.0 |
| AI 供应商 | **StepFun 单一供应商** | 文本 `step-3.7-flash` / 图片 `step-image-edit-2` / 语音 `stepaudio-2.5-tts` |

| 环境标识 | AppID `wx231962cec75efb9e` / envId `blacke-d7g0wczgza0632d5a` | — |

## 二、关键讨论节点与决策过程

项目在 2026 年 7 月集中完成架构定型，以下为关键节点的决策脉络（按时间线）：

### 节点 1 · 前端状态管理与分包策略（2026-07-19）
- **议题**：是否引入 Mobx / Pinia 等状态库？包体积如何控制？
- **决策**：**不引入**第三方状态库，自研轻量 Store（React Context + useReducer）；主包严格 ≤1.5MB，重功能拆为三个分包。
- **理由**：节省包体积、降低依赖风险；分包隔离非首屏模块（声音复刻、故事宝库、用户中心）。

### 节点 2 · 认证与会话安全
- **议题**：小程序登录态如何设计？`session_key` 放哪？
- **决策**：`wx.login` 后端 code2Session 兑换会话，`Bearer base64` Token + 7 天过期 + 路由白名单中间件；**`session_key` 仅存后端，绝不返回前端**（遵循微信安全规范）。
- **配套**：401 自动刷新 + 并发锁（避免多请求同时刷新导致 token 覆盖）；缓存优先 + 后台静默刷新（stale-while-revalidate）。

### 节点 3 · 多用户数据隔离
- **议题**：多家庭共用一套云环境，数据如何隔离？
- **决策**：`users: Record<openid, UserData>` 结构 + 自动迁移 + 新用户默认权益；`GET /api/db` 改造为"用户级 + 全局数据分离返回"。
- **原则**：**后端 `DBState` 为权威数据源**，前端缓存仅作展示与离线兜底；前端禁止本地写入业务态，写操作一律走后端 API，写入成功后主动失效相关缓存。

### 节点 4 · 异步音频任务编排
- **议题**：TTS + 章节图生成耗时不可控，同步接口易超时。
- **决策**：引入 **jobId 状态机** `queued → tts_generating → mixing → ready/failed` + 轮询端点；封面图 / 章节图 / 配音各自重试 3 次；绘本图全部 AI 成功才算 `ready`，否则 `failed`。
- **边界**：配音（TTS）失败仅影响"可听"，不影响"可看"；图缺失整体判失败，避免误导用户。

### 节点 5 · AI 供应商收敛
- **议题**：是否多模型混用？
- **决策**：**StepFun 单一供应商**，移除 Gemini。文本 / 图片 / 语音三模态统一接入，降低集成与运维成本。

### 节点 6 · 儿童内容安全合规
- **议题**：面向儿童，如何防止有害内容？
- **决策**：首次进入弹隐私协议；录音 / 手机号按需触发并展示用途说明；**三层安全校验**（输入校验 → 提示词二次校验 → 生成内容输出校验），命中敏感词则拦截或儿童友好改写，并**全额退还额度**。

### 节点 7 · 部署即固化 mp-admin 权限（2026-07-22 根治）
- **议题**：每次 `tcb fn deploy` 会把 `mp-admin` 调用权限重置回默认 `auth != null`，而网页后台用匿名登录正好被排除 → `PERMISSION_DENIED`。
- **决策**：固化方案 —— 部署脚本末尾自动调用 `apply-mpadmin-permission.js`（复用本地 tcb 登录态 STS + TC3 签名写入 `mp-admin:{invoke:true}`，函数内部 adminToken HMAC 兜底）。任何重部署 mp-admin 后必须重设权限。

### 节点 8 · 前后端契约对齐（2026-07-22）
- **议题**：前端乐观更新与错误提示以何为权威？
- **决策**：**改前端必须对照后端 action 的真实返回结构**（尤其 `success` 布尔与字段名），两端契约对齐，禁止只看前端判定功能正常。

## 四、关键提示词（Prompt）及其作用与最佳实践 ⭐

伴梦的 AI 能力由三条生成管线构成，每条管线都有独立的提示词策略。**所有 AI 密钥仅在云函数环境变量中，提示词构造与调用全部在后端完成，绝不暴露前端。**

### 4.1 故事文本生成提示词（`buildStoryTextPrompt`）

**作用**：把家长的向导输入（主题 / 教育目标 / 场景 / 角色 / 时长）转化为结构化中文绘本故事 JSON。

**角色定位**：system prompt 设定为儿童绘本作家；user prompt 仅一句触发语（"请立即开始创作关于…"）。

**核心结构**：
- 受众锚定：`Write in Chinese for a {age}-year-old child`
- 内容约束：主题 / 教育目标 / 场景 / 整体情绪 / 场景设定
- 角色设定：逐条列出主角姓名、身份、性格、补充描述
- 叙事节奏：模板 `chapterBeats` 用 `→` 串联
- 时长约束：明确返回章节数与每章字数
- 输出契约：**只返回 JSON，不要 Markdown 代码块**，并显式声明 schema
- 关键护栏："这里仅生成故事文字，不生成封面 / 内页图片提示词，图片提示词由系统使用独立策略生成"

**工程参数最佳实践**（来自 `stepfun.js`）：
| 参数 | 取值 | 理由 |
|---|---|---|
| `response_format` | `json_object` | 强制 JSON 输出，便于解析 |
| `temperature` | `0.75` | 温暖但有变化，避免机械重复 |
| `reasoning_effort` | `'low'` | `step-3.7-flash` 是推理模型，绘本创作无需深度推理 → 省 token、提速 |
| `max_tokens` | `4096` | 不设会被截断 → `finish_reason:length` → `JSON.parse` 失败 |
| 解析前处理 | 剥离 ```` ```json ```` 围栏 | 部分推理模型会在 JSON 外套代码块 |

> **最佳实践**：输入校验 → **提示词二次校验** → 输出校验，三层安全防线贯穿始终。

### 4.2 封面插图提示词（`buildCoverImagePrompt`）

**作用**：生成"绘本封面"而非内页——确立一个焦点角色 + 整体故事氛围 + 视觉钩子，让孩子想翻开书。

**关键约束**：
- `portrait` 构图，明确"not an interior page"
- **角色一致性**：`Keep the character design consistent for future pages`（与内页统一）
- 风格三件套：`medium`（水彩绘本风）/ `palette` / `lighting` 从模板注入
- **硬性禁项**：`No text, no title, no letters, no logo, no watermark, no scary or violent elements`

### 4.3 章节插图提示词（`buildChapterImagePrompt`）

**作用**：内页插图，聚焦"当前章节的具体动作 + 角色表情 + 情节推进"，而非概括整本故事。

**关键约束**：
- `Preserve the exact design from the cover`——**角色一致性靠显式约束，而非依赖模型记忆**
- 以章节正文 `text` 作为"动作与情绪节拍"输入
- 可读性构图：`readable landscape or square`，前景动作 + 平静安全的背景
- 同样强制 `No text / logo / watermark`

> **封面 vs 内页分离策略**（重要设计）：封面 = 焦点角色 + 整体氛围；内页 = 当前章节动作 + 情节推进。两者风格三件套一致，但语义任务完全不同，不能混用同一提示词。

### 4.4 语音合成（TTS）与声音克隆

**TTS 无自然语言 prompt**，靠 `voice` 参数选择音色：
- 妈妈温柔女声 `wenrounvsheng`（默认）
- 爸爸磁性男声 `cixingnansheng`
- 克隆音色 `stepfunVoiceId`（取自用户声纹克隆结果）

**声音克隆的"提示词"即朗读内容**（`CLONE_SAMPLE_TEXT`）：
```
太阳下山了，小鸟回家了，小宝宝闭上眼睛，乖乖睡个好觉。
```

**克隆最佳实践**（来自 `studio/index.tsx` 与 `stepfun.js`）：
1. **录音实际朗读内容 == 克隆请求 `text`**（StepFun 内部 ASR 比对，CER 越低越好）
2. 文本越短、朗读越清晰 → CER 越低 → 克隆成功率越高
3. 选词：常见字、无生僻字、少轻声 / 儿化、亲子睡前语境
4. 音频时长 **5–10 秒**；格式 **WAV**（StepFun 的 MP3 解码器无法处理微信 `RecorderManager` 生成的 MP3）
5. 采样率 **22.05kHz 单声道 16bit PCM**（比 16kHz 更利于 ASR）
6. 失败友好分级：`INVALID_AUDIO_FILE`（格式问题）/ `validate|CER|NOT_PASS`（朗读不匹配）→ 提示"在安静环境用清晰语速大声朗读示范文本后重试"

### 4.5 跨管线可复用提示词要点（速览）

| # | 要点 | 做法 |
|---|---|---|
| 1 | 角色分离 | system 定身份 / 约束，user 只给触发语 |
| 2 | 结构化输出契约 | 显式声明 JSON schema + `response_format` + 解析前清洗围栏 |
| 3 | 推理模型降档 | 非推理任务设 `reasoning_effort: low` 省 token 提速 |
| 4 | 防截断 | 给足 `max_tokens`，否则 `finish_reason:length` 破坏解析 |
| 5 | 内容安全三道防线 | 输入 → 提示词 → 输出，儿童产品必做 |
| 6 | 图像角色一致性 | 显式 continuity 约束 + 风格三件套，不靠模型记忆 |
| 7 | 生产者 / 消费者解耦 | 封面 / 内页独立策略；音频用 jobId 状态机异步解耦 |
| 8 | 失败不造假 | 图生成失败留空，绝不用 stock 图伪装成 AI 输出 |
| 9 | 中英分工 | 图像提示词用英文（StepFun 依从度更高）；故事文本用"英文角色框架 + 中文内容" |
| 10 | 密钥与渲染分离 | AI 密钥只在云函数环境变量，提示词构造在服务端 |

## 五、附录 · 关键提示词原文片段（便于直接复用）

### 故事文本 system prompt（节选）
```
You are an expert children's picture-book author. Write in Chinese for a {age}-year-old child.
主题：{theme}；教育目标：{educationalGoal}；场景：{scene}。
整体情绪：{mood}。场景设定：{setting}，可使用{details}作为安全、可爱的画面细节。
角色设定：{characters}
模板叙事节奏：{chapterBeats.join(' → ')}。
时长要求：{durationDesc}，请严格返回 {expectedChapters} 个章节。
保持语言温暖、具体、积极，避免说教，让教育目标通过角色的选择和行动自然呈现。
只返回 JSON，不要 Markdown 代码块，结构必须是：
{"title":"中文故事名","abstract":"1-2句故事简介","chapters":[{"chapterNumber":1,"title":"章节标题","text":"章节正文"}]}
注意：这里仅生成故事文字，不生成封面提示词，也不生成内页图片提示词。图片提示词由系统使用独立策略生成。
```

### 封面图 prompt（节选）
```
Create an attractive portrait children's picture-book COVER, not an interior page.
Story title concept: {title}. Story premise: {abstract}.
Theme: {theme}; overall atmosphere: {mood}; setting: {setting}.
Main character: {name}, {role}, {personality}.
Cover strategy: {coverPromptSeed}; establish one memorable focal character and the overall story mood...
Visual style: {medium}; palette: {palette}; lighting: {lighting}.
Do not depict a specific chapter event. Keep the character design consistent for future pages: {characterContinuity}.
No text, no title, no letters, no logo, no watermark, no scary or violent elements.
```

### 章节图 prompt（节选）
```
Create an interior children's picture-book illustration for chapter {n}, not a cover.
Chapter action and emotional beat: {text}.
Setting: {setting}; supporting details: {details}.
Content-page strategy: {contentPromptSeed}; focus on the concrete action, character expression, and plot progression...
Main character: {name}, {role}. Preserve the exact design from the cover: {characterContinuity}.
Use a readable landscape or square story-page composition with foreground action and a calm, safe background.
No text, no title, no letters, no logo, no watermark, no scary or violent elements.
```
