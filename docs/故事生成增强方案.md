# 伴梦童话 · 故事生成增强技术方案

> 状态：设计稿（评审通过后再实现）
> 日期：2026-08-07
> 目标：让故事生成"调用宝宝信息 + 可配置的 AI 身份（儿童故事作家）"，并在后台提供"故事生成维护"功能。
> 维护粒度（已确认）：**人设 + 关键片段可调，提示词结构代码锁死**（不全文模板编辑，避免运营改坏 JSON 契约）。

---

## 0. 现状结论（核查依据）

| 诉求 | 现状 | 缺口 |
|---|---|---|
| 调用宝宝信息 | 向导页有"宝宝资料"页，仅读 `db?.profile?.age`；后端 `users.profile = {}` 空占位，**全项目无任何 profile 写回代码** | 无持久化儿童档案，故事生成只用向导临时传的 `age`+`mainCharacters`，未织入档案 |
| AI 身份提示词 | `storybook.js:buildStoryTextPrompt` 硬编码 `"You are an expert children's picture-book author. Write in Chinese for a {age}-year-old child."` | 人设写死，不可运营调整 |
| 后台维护 | 已有 `ThemeConfig`（主题/场景）、`AiConfig`（模型选型+监控） | 缺"故事生成配置中心"：AI 人设、提示词片段、儿童档案均无维护入口 |

设计原则：沿用项目已有的 **「单一数据源 + 5 分钟 TTL + 兜底默认值」** 模式（参考 `storyConfig` / `themeConfig`）。

## 2. 模块一：宝宝信息档案（持久化 + 织入提示词）

### 2.1 数据模型（固化到 `users` 文档的 `profile` 字段）

```js
// cloudfunctions/mp-user/common/db.js — getDefaultUserData() 中
profile: {
  childName: '',      // 宝宝小名，如"团团"
  age: 4,             // 岁
  gender: '',         // 'boy' | 'girl' | '' 可选
  traits: [],         // 性格标签，如 ['温柔敏感','喜欢听故事']
  favoriteTheme: '',  // 偏好主题 key（可选，用于默认推荐）
  favoriteScene: '',  // 偏好场景 key（可选）
  avatarUrl: '',      // 宝宝头像（可选）
  updatedAt: '',
}
```

### 2.2 写入时机（两处入口）

1. **向导页"宝宝资料"步骤**：当前只 `db?.profile?.age` 读取、无保存。改为：该步骤完成时调用 `mp-user` 的 `profile/save` 写回。
2. **（可选）独立"宝宝档案"页**：放在 `profile`（我的）分包下，支持随时修改；首启若 `profile.childName` 为空则引导填写。

### 2.3 后端 action（`mp-user`）

```js
// cloudfunctions/mp-user/index.js 新增
case 'profile/get':   // 返回当前 openid 的 profile
case 'profile/save':  // 入参部分字段，合并写回 users.profile，打 updatedAt
```

> 多用户数据隔离已存在（users 按 openid 归属），profile 自然隔离，无需额外处理。

### 2.4 织入提示词（mp-story 侧）

`generateText` 里取 `userState.profile`，构造一段"宝宝信息指令"文本，交给 `buildStoryTextPrompt`：

```
宝宝信息：小名"{childName}"，{age}岁{genderText}，性格{traits.join('、')}。
请优先以"{childName}"作为故事小主角，并将其性格特质自然融入情节，让故事像专为他/她定制。
```

- profile 缺失/为空 → 回退现有文案 `"主角是一位勇敢可爱的小宝贝。"`（零回归）。
- 该指令文本本身也走敏感词扫描（复用 `runSafetyCheck`）。

## 3. 模块二：可配置 AI 身份与提示词（人设 + 关键片段可调）

### 3.1 配置文档 `storyPromptConfig`（DB，单一数据源）

- **集合**：复用现有 `storyConfig` 集合，新增文档 `_id: 'promptConfig'`（与 `themeConfig` 同集合，统一管理）。
- **加载**：新增 `ensureStoryPromptConfig()`，与 `ensureStoryConfig()` 同策略——5 分钟 TTL + 并发去重 + 缺失懒写默认值（兜底）。
- **默认值**（首次请求自动 seed，与当前线上行为一致）：

```js
{
  _id: 'promptConfig',
  systemIdentity: "You are an expert children's picture-book author. Write in Chinese for a {age}-year-old child.",
  childProfileInstr: '宝宝信息：{childProfile}。请优先以宝宝小名作为故事小主角，并将其性格特质自然融入情节，让故事像专为他/她定制。',
  openingTone: '保持语言温暖、具体、积极，避免说教。',
  endingAnchor: '让教育目标通过角色的选择和行动自然呈现，结尾回到安全、温暖的情绪落点。',
  temperature: 0.75,
  maxTokens: 4096,
  reasoningEffort: 'low',
  updatedAt: null,
}
```

> 占位符约定：`{age}`（数字）、`{childProfile}`（模块二.4 构造的文本）。其余字段（主题/场景/角色/章节节奏/时长/JSON 结构）**代码锁死，不暴露**。

### 3.2 结构受控的拼装策略（`buildStoryTextPrompt` 改造）

代码骨架保持不变，仅把"人设行 / 宝宝指令行 / 语气行 / 落点行"替换为配置值：

```
[systemIdentity 替换 {age}]                      ← 可配
主题：{theme}；教育目标：{educationalGoal}；场景：{scene}。
整体情绪：{mood}。场景设定：{setting}，可使用{details}。
角色设定：{characters 或 '主角是一位勇敢可爱的小宝贝。'}
[childProfileInstr 替换 {childProfile}]          ← 可配（含宝宝档案）
模板叙事节奏：{chapterBeats →}
时长要求：{durationDesc}，请严格返回 {expectedChapters} 个章节。
[openingTone]                                    ← 可配
[endingAnchor]                                   ← 可配
只返回 JSON，不要 Markdown 代码块，结构必须是：   ← 锁死
{"title":...,"abstract":...,"chapters":[...]}
注意：这里仅生成故事文字，不生成封面/内页图提示词（独立策略生成）。
```

**为什么不全文模板编辑**：JSON 契约、字段顺序、封面/内页分离约束是稳定性命脉，放给运营改极易"改坏导致解析失败"。只开放"人设 + 3 个文本片段 + 温度/字数"，既满足调声音的需求，又保证结构不崩。

### 3.3 模型参数透传

`stepfun.generateText(systemPrompt, titleHint, { temperature, maxTokens, reasoningEffort })`：
- `temperature` / `maxTokens` 取自 `promptConfig`（替换当前写死的 `0.75` / `4096`）。
- `reasoning_effort: 'low'` 维持（绘本创作不需要深度推理，省 token 提速）。

### 3.4 改造点清单（mp-story）

- `common/storybook.js`：新增 `ensureStoryPromptConfig()` + 默认值；`buildStoryTextPrompt(input, template, expectedChapters, durationDesc, childProfileText, promptConfig)` 改为接收配置与宝宝文本。
- `common/stepfun.js`：`generateText` 增加 `opts` 参数透传 `temperature`/`maxTokens`。
- `index.js:generateText`：取 `userState.profile` → 构造 `childProfileText` → 取 `promptConfig` → 传入；并把 `temperature`/`maxTokens` 透传给 StepFun。

## 4. 模块三：后台"故事生成维护"页

### 4.1 页面：`admin/src/pages/StoryPromptConfig.tsx`

与 `ThemeConfig.tsx`（主题/场景）、`AiConfig.tsx`（模型/监控）并列，专注"故事文字怎么写"。

### 4.2 表单字段

| 字段 | 控件 | 说明 | 占位符 |
|---|---|---|---|
| 儿童故事作家人设 `systemIdentity` | TextArea | AI 身份/语气总设定 | 支持 `{age}` |
| 宝宝信息织入指令 `childProfileInstr` | TextArea | 如何把宝宝档案织进故事 | 支持 `{childProfile}` |
| 开头语气 `openingTone` | Input | 如"温暖、具体、积极，避免说教" | — |
| 结尾落点 `endingAnchor` | TextArea | 如"教育目标自然呈现，回到温暖落点" | — |
| 创造力 temperature | InputNumber 0–1 | 默认 0.75 | — |
| 最大 token maxTokens | InputNumber | 默认 4096（防 JSON 截断） | — |

- 页面加载时 `callAdmin('prompt-config/get')` 拉取；保存 `callAdmin('prompt-config/save', values)`。
- 提供"恢复默认"按钮（写回内置默认值）。
- **（可选）儿童档案区**：表格列出已填写 profile 的用户，支持查看/快速编辑 `childName/age/traits`（运营辅助，非必须）。

### 4.3 与现有页关系

- 主题/场景 → `ThemeConfig`（不动）
- 模型选型/调用监控 → `AiConfig`（不动）
- **新增**：`StoryPromptConfig`（人设 + 提示词片段 + 温度/字数 + 可选档案）
- 路由注册到 `admin/src/router`（或菜单配置），与现有页面同级。

### 4.4 后端 action（admin 网关）

`mp-admin` 新增（或 `mp-story` 内 admin 鉴权）：
```js
case 'prompt-config/get':  // 读 storyPromptConfig 文档
case 'prompt-config/save': // 校验字段、合并写回、打 updatedAt（admin token 鉴权）
```
> 鉴权沿用 `mp-admin` 既有 HMAC 令牌机制，与 `theme-config/save` 一致。

## 7. 上线与回滚保障（零回归原则）

1. **兜底默认值 = 当前线上硬编码值**：`promptConfig` 文档缺失时，seed 用现有字符串，行为与今天完全一致。
2. **profile 缺失回退**：无档案 → 仍用 `"主角是一位勇敢可爱的小宝贝。"`，不影响现有生成。
3. **配置加载失败**：`ensureStoryPromptConfig` try/catch，异常时退回内存默认值（与 `ensureStoryConfig` 同策略），绝不阻断生成。
4. **敏感词扫描不放松**：宝宝信息织入文本、人设文本仍走 `runSafetyCheck`。
5. **发布节奏**：先发后端云函数（带兜底），再发前端；后台页独立可灰度。建议先在 `promptConfig` 默认值不动的情况下发版验证，再在后台慢慢调人设。
